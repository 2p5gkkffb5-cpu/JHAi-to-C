## 推荐发布方式

最安全的方式是保留当前私有仓库作为开发历史，在一个新的公开仓库中只导入经过审核的当前源码快照：

1. 从已验证提交导出干净工作树，不携带原 `.git` 历史。
2. 排除数据库、checkpoint、上传内容、QA 产物、内部报告和未确认授权的素材。
3. 保留所有者确认的 `LICENSE`，运行密钥扫描、前后端测试和构建。
4. 以单一初始提交推送公开仓库，设置描述、Topics、默认分支保护和私密漏洞报告。
5. 发布首个带变更说明的版本，并在 README 中提供可复现的 Mock 演示或在线 Demo。

采用新仓库可以避免强制重写现有协作分支，也能保留内部审计和开发历史。若必须沿用当前 GitHub 仓库，则需要单独批准历史重写与强制推送。
